없는 기능은 흉내내지 않는다. 데스크탑 우측 레일은 files / terminal / review 탭이지만 셋 다 Electron 로컬 접근이라 HTTP로 재현할 수 없다. 그래서 태블릿 우측 레일은 게이트웨이가 실제로 노출하는 것 — 열린 세션의 도구 실행 목록 — 을 보여준다.

서버 이벤트가 화면이 되는 방식

앱에는 자체 상태 기계가 거의 없다. /v1/runs/{id}/events가 흘리는 아홉 개 프레임이 곧 화면 전환이다. 전부 이름 없는 data: 프레임이고 종류는 JSON 본문의 event 키에 들어 있다.

이벤트화면알림
message.delta 어시스턴트 말풍선에 누적대화 본문은 전부 이 경로로 온다. 스트리밍 중에는 끝에 커서 블록 —
reasoning.available 추론 블록으로 접어서 표시 —
tool.started 도구 카드 생성, 왼쪽 띠 황동 + 진행 바 —
tool.completed 같은 카드가 초록(또는 실패 시 빨강)으로, 소요 시간 표시 —
approval.request 승인 시트가 올라오고 대화가 잠긴다도구 카드는 호박색 “승인 대기”로 바뀐다 고우선 알림 + 액션 버튼
approval.responded 시트가 내려가고 스트림 재개 알림 해제
run.completed 중단 바 사라지고 컴포저 활성화 완료 알림 (설정에서 끔 가능)
run.failed 인라인 오류 카드 실패 알림
run.cancelled 세션 목록에서 회색 점 —
스트림에 없는 두 가지. run.stopping은 이벤트가 아니라 실행 상태값이라 GET /v1/runs/{id}로만 관측된다. hermes.tool.progress는 /v1/chat/completions 스트림의 named 이벤트이고 이 경로에는 나오지 않는다. 파서는 두 형식을 모두 읽지만 앱이 쓰는 경로는 위 아홉 개다.
앱이 정책을 복제하지 않는다. 승인 선택지, 도구 이름, 모델 목록은 전부 서버 응답에서 온다. 앱이 고정으로 아는 것은 엔드포인트 경로, 이벤트 이름 일곱 개, 승인 문자열 네 개뿐이다.
